# ADR-006: Правила определения слабых тем

- Статус: принято для Release 4.1
- Дата: 2026-11-12
- Область: детерминированные учебные сигналы

## Контекст

Adaptive Learning должен показывать темы, которым требуется внимание, но не
объявлять новую тему слабой и не скрывать причины за непрозрачным общим баллом.
Доступные факты имеют разный смысл: `Again` означает неуспешное воспроизведение,
`Hard` — успешное, но трудное; AI-полнота необязательна; просроченность отражает
план повторений, а не обязательно непонимание.

Нужны стабильные правила, одинаково работающие с включённым и выключенным AI.

## Решение

### 1. Период анализа

API использует скользящее окно в целых локальных календарных днях:

- `period_days` от 7 до 365, по умолчанию 30;
- начало — полночь первого дня в `APP_TIMEZONE`;
- конец — фактическое время формирования ответа;
- в будущие даты данные не попадают.

Ответ возвращает `period_start`, `generated_at` и timezone, чтобы граница была
видна клиенту.

### 2. Какие данные учитываются

Для каждой темы считаются только данные её неархивных карточек:

- активные и просроченные карточки на момент запроса;
- подтверждённые `review_logs` внутри периода;
- сохранённые `answer_evaluations` внутри периода;
- дата последнего подтверждённого повторения за всё время.

AI-оценки не обязательны и не заменяют пользовательскую оценку SM-2. Повтор
идемпотентного AI-запроса уже представлен одной сохранённой оценкой и поэтому не
увеличивает метрики повторно.

### 3. Достаточность истории

Тема имеет достаточную историю, если существует хотя бы одно из условий:

- не менее трёх подтверждённых повторений за период;
- не менее трёх AI-оценок письменных ответов за период.

Если активных карточек нет, статус всегда `insufficient_data` с причиной
`no_active_cards`. Если карточки есть, но оба порога не достигнуты, статус —
`insufficient_data` с причиной `insufficient_history`.

### 4. Причины `needs_attention`

При достаточной истории тема получает `needs_attention`, если выполняется хотя
бы одно правило:

| Причина | Правило |
|---|---|
| `frequent_again` | `Again` составляют не менее одной трети повторений |
| `frequent_hard` | `Hard` составляют не менее половины повторений |
| `low_ai_completeness` | есть минимум две AI-оценки и средняя полнота ниже 70 |
| `overdue_backlog` | минимум две активные карточки и не менее половины просрочены |
| `long_inactivity` | есть просроченная карточка, а последнее повторение было более 14 дней назад |

Все сработавшие причины возвращаются одновременно. Если история достаточна и ни
одно правило не сработало, статус равен `stable`.

Граница `frequent_again` сравнивается целочисленно как
`again_reviews * 3 >= reviews`, чтобы не зависеть от округления `float`.
Аналогично половина сравнивается через удвоенное количество.

### 5. Возвращаемые показатели

Для объяснения статуса API возвращает исходные счётчики и производные доли:

- active/overdue cards и overdue rate;
- reviews, Again, Hard, successful reviews;
- success, Again и Hard rates;
- количество AI-оценок, средние score и completeness;
- дату последнего повторения;
- status и полный список reasons.

`successful_reviews` сохраняет существующее правило статистики: успешными
считаются `Hard`, `Good` и `Easy` (`quality >= 3`). `Hard` одновременно входит
в успешные повторения и отдельный сигнал трудности.

### 6. Нет общего скрытого score

Release 4.1 не складывает показатели в единый «процент знания». Разные причины
не имеют доказанных весов, а число 73 или 81 создавало бы ложную точность.
Сортировка показывает сначала `needs_attention`, затем `insufficient_data`,
затем `stable`; внутри статуса — по категории, теме и UUID.

## Контрольные примеры

| История за период | Результат |
|---|---|
| Новая тема, 0 повторений | `insufficient_data` |
| 2 `Again` | `insufficient_data`, несмотря на ошибки |
| `Again`, `Good`, `Good` | `needs_attention: frequent_again` |
| `Hard`, `Hard`, `Good` | `needs_attention: frequent_hard` |
| 3 `Good`, просрочена 1 из 3 карточек | `stable` |
| 3 `Good`, просрочены 2 из 3 карточек | `needs_attention: overdue_backlog` |
| 3 AI-оценки со средней полнотой 60, без review | `needs_attention: low_ai_completeness` |
| 3 `Good`, AI не использовался | `stable` |

## Инварианты

- одинаковая история и время дают одинаковый результат;
- отсутствие AI не ухудшает статус;
- архивные карточки не влияют на текущий учебный план;
- статус не меняет данные и расписание;
- одна тема возвращается не более одного раза;
- фильтрация по статусу выполняется после применения тех же правил, что видит
  пользователь.

## Последствия

Пороговые значения намеренно консервативны и могут быть изменены только вместе
с ADR, контрольными примерами и тестами. После накопления реальной истории можно
сравнить правила с пользовательской оценкой полезности рекомендаций, не меняя
исходные факты.
