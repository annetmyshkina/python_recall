# План работ Release 2: Frontend

- Статус: согласован для последовательной реализации
- Дата: 2026-11-07
- Результат релиза: карточки можно создавать, находить и повторять через браузер

## Правила выполнения

Этапы выполняются последовательно. На каждом этапе функциональность и её тесты
появляются вместе. После завершения этапа:

1. запускаются относящиеся к нему проверки;
2. результат кратко объясняется;
3. изменения фиксируются отдельным коммитом;
4. только затем начинается следующий этап.

Итоговый этап не заменяет текущее тестирование, а повторно проверяет Release 2
целиком на production build и настоящем Backend.

- определить маршруты и структуру исходного кода;
- зафиксировать интеграцию с OpenAPI и обработку ошибок;
- отделить Release 2 от AI-сценариев Release 3;
- определить тестовую стратегию и критерии готовности.

**Проверки:** ссылки документации, формат Markdown, отсутствие противоречий с
`spec.md`, `docs/api.md` и существующими ADR.

**Предлагаемый коммит:** `docs: define release 2 frontend architecture`

## 2.1. Каркас Frontend

**Результат:** приложение запускается, собирается и показывает начальный маршрут.

- создать Vite-проект React + TypeScript в `frontend/`;
- подключить React Router, TanStack Query, Tailwind CSS и тестовую среду;
- настроить TypeScript strict, lint, Vitest и React Testing Library;
- добавить генерацию API-типов из `docs/openapi.yaml`;
- настроить Vite proxy `/api` на локальный Backend;
- добавить frontend-команды в корневой Makefile и инструкции в README;
- добавить минимальные smoke/component tests корневого приложения.

**Проверки:** install lockfile, API type generation check, typecheck, lint, tests,
production build.

**Предлагаемый коммит:** `feat: bootstrap react frontend`

## 2.4. Повторение

**Результат:** полный SM-2 сценарий проходится в браузере без AI.

- запросить очередь повторения и показать её состояние;
- отобразить вопрос и необязательное поле пользовательского ответа;
- сохранить введённый ответ отдельно от оценки;
- показать эталонный ответ только после явного действия;
- добавить Again, Hard, Good и Easy с понятными подписями;
- создать и повторно использовать idempotency key для одной команды;
- после подтверждения показать новое расписание и перейти к следующей карточке;
- обработать пустую очередь, архивирование и конфликт идемпотентности.

**Тесты вместе с кодом:** устный ответ без попытки, письменный ответ, раскрытие
эталона, четыре оценки, защита от двойного клика, ошибки и завершение очереди.

**Проверки:** typecheck, lint, tests, production build и review smoke с настоящим
Backend.

**Предлагаемый коммит:** `feat: implement review interface`

**Проверки:** typecheck, lint, tests, production build и statistics smoke с
настоящим Backend.

**Предлагаемый коммит:** `feat: add dashboard and learning statistics`

## Критерии готовности Release 2

- приложение запускается локально и через Docker Compose;
- категории, темы, теги и карточки управляются через UI;
- поиск, фильтры и пагинация сохраняются в URL;
- повторение полностью работает без AI и изменяет SM-2 только через Backend;
- Dashboard и статистика используют реальные REST endpoints;
- ошибки API объясняются пользователю без утечки технических деталей;
- ключевые сценарии покрыты component/integration tests;
- typecheck, lint, tests и production build проходят одной командой;
- AI-функции остаются явно за границей Release 2.
