# План работ Release 3: AI Mentor

- Статус: согласован для последовательной реализации
- Дата: 2026-11-09
- Результат релиза: локальный ИИ анализирует ответы и карточки, а новые карточки
  появляются только как подтверждаемые предложения

## Правила выполнения

Этапы выполняются последовательно. Функциональность, миграции, OpenAPI-контракт
и тесты появляются вместе. После каждого этапа:

1. запускаются относящиеся к нему проверки;
2. результат проверяется вручную, если появляется пользовательский сценарий;
3. изменения фиксируются отдельным коммитом;
4. только затем начинается следующий этап.

AI остаётся необязательным. Ни один этап не должен ломать базу знаний,
повторения и статистику при выключенном или недоступном Ollama.

## 3.0. Архитектура и границы релиза

**Результат:** [ADR-004](adr/ADR-004-ai-architecture.md) и этот план.

- выбрать границу провайдера и способ structured output;
- зафиксировать Ollama как единственный провайдер Release 3;
- разделить provider, scenario и persistence слои;
- определить правила идемпотентности, ошибок и учёта использования;
- не связывать AI-результат с изменением SM-2;
- отложить облачные провайдеры и Adaptive Tutor до Release 4.

**Проверки:** документация не противоречит ADR-001/002/003, `spec.md` и
существующей доменной модели; ссылки ведут на официальную документацию Ollama.

**Предлагаемый коммит:** `docs: define release 3 ai architecture`

## 3.1. Основа провайдера Ollama

**Результат:** Backend умеет безопасно проверить Ollama и получить
валидированный структурированный ответ без участия базы данных.

- добавить AI-настройки с явным выключателем и безопасными defaults;
- создать provider protocol, типизированный результат и ошибки границы;
- реализовать Ollama adapter поверх `httpx.AsyncClient`;
- использовать `/api/tags` для readiness модели и `/api/chat` для генерации;
- добавить provider manager без автоматического fallback;
- добавить `GET /ai/providers` и независимый `GET /health/ai`;
- расширить OpenAPI-контракт и сгенерированные Frontend-типы;
- не создавать AI-таблицы на этом этапе.

**Тесты вместе с кодом:** AI выключен, Ollama недоступен, модель отсутствует,
успешный structured response, timeout, HTTP error, невалидный JSON и schema
validation error. Core health при этом остаётся healthy.

**Проверки:** backend check, OpenAPI check, provider tests и ручная проверка
readiness установленного `qwen3:4b`.

**Предлагаемый коммит:** `feat: add ollama provider foundation`

## 3.2. Answer Evaluator API и хранение

**Результат:** сохранённую попытку ответа можно проанализировать и позднее
получить тот же неизменяемый результат.

- согласовать Pydantic-схему оценки: правильность, полнота, score, пропущенные
  понятия, ошибки, обратная связь и рекомендация;
- добавить versioned prompt Answer Evaluator;
- добавить миграцией `ai_requests`, `answer_evaluations` и `ai_usage_logs`;
- связать оценку с `AnswerAttempt` через `RESTRICT`;
- сохранять provider, model, prompt version и входной snapshot;
- реализовать `POST /ai/evaluate-answer` и чтение сохранённых оценок;
- защитить команду `Idempotency-Key`;
- логировать успешный и ошибочный вызов без prompt и ответа пользователя;
- не менять Card, ReviewLog и состояние SM-2.

**Тесты вместе с кодом:** happy path, `needs_review`, повторный анализ с новым
ключом, idempotent replay, параллельный request, конфликт ключа,
архивная/отсутствующая карточка, provider errors, невалидный structured output,
транзакционный rollback и token usage.

**Проверки:** миграции upgrade/downgrade/check, backend check, OpenAPI check и
smoke с fake provider.

**Предлагаемый коммит:** `feat: add answer evaluation api`

## 3.3. AI-анализ в повторении

**Результат:** пользователь может запросить анализ письменного ответа и затем
самостоятельно выбрать оценку повторения.

- показывать кнопку анализа только для сохранённого письменного ответа;
- отображать состояние Ollama и понятную причину недоступности;
- показать score, полноту, ошибки, пропущенные понятия и рекомендацию;
- повторять неопределённый сетевой ответ с тем же ключом;
- после завершившейся AI-ошибки начинать новый анализ с новым ключом;
- сохранить возможность сразу выбрать «Не помню / Трудно / Хорошо / Легко»;
- не подставлять AI-score в SM-2 и не блокировать завершение сессии.

**Тесты вместе с кодом:** анализ необязателен, устный ответ без анализа,
успешный результат, `needs_review`, unavailable/timeout/invalid response,
идемпотентный retry и независимость пользовательской оценки.

**Проверки:** frontend check, backend regression, production build и ручной
Review-сценарий с локальным Ollama.

**Предлагаемый коммит:** `feat: integrate ai answer feedback into reviews`

## 3.4. Card Analyzer

**Результат:** карточку можно проверить и применить предложенные правки только
явным действием пользователя.

- определить отдельную схему качества карточки;
- добавить versioned prompt и миграцию `card_analyses`;
- реализовать `POST /ai/analyze-card` и историю анализов карточки;
- проверять ясность, конкретность, корректность и учебную ценность;
- возвращать проблемы и предлагаемые question/answer/explanation/code example;
- добавить анализ в форму карточки;
- применять выбранные предложения через обычный Card PATCH после подтверждения;
- не менять карточку внутри AI-сервиса.

**Тесты вместе с кодом:** хороший и проблемный результат, пустые предложения,
provider failure, повторный анализ, идемпотентность, сохранение истории,
частичное и полное применение правок пользователем.

**Проверки:** миграции, backend/frontend checks, production build и ручной
анализ существующей карточки.

**Предлагаемый коммит:** `feat: add ai card analysis workflow`

## 3.5. Card Generator и предложения

**Результат:** модель генерирует черновики, которые не попадают в базу знаний до
подтверждения.

- определить схему пакета сгенерированных карточек и лимиты количества;
- добавить versioned prompt и миграцию `ai_suggestions`;
- реализовать генерацию по теме и пользовательскому конспекту;
- выполнять детерминированную проверку точных/нормализованных дубликатов;
- сохранять каждую карточку как `pending` suggestion;
- добавить list/filter/pagination для предложений;
- реализовать транзакционные accept/reject;
- при accept создавать Card и фиксировать итоговый статус;
- запретить повторное принятие и автоматическое сохранение.

**Тесты вместе с кодом:** лимиты, частично невалидный пакет, дубликаты,
идемпотентность, provider errors, pending/accepted/rejected transitions,
конкурентное принятие и rollback создания карточки.

**Проверки:** миграции, backend check, OpenAPI check и API smoke с fake
provider.

**Предлагаемый коммит:** `feat: add generated card suggestions`

## 3.6. Интерфейс предложений и использования

**Результат:** пользователь управляет предложениями и видит работу локальной
модели без технического шума.

- добавить отдельный раздел ИИ-наставника;
- запускать генерацию из выбранной темы или текста;
- показывать pending suggestions с предпросмотром;
- подтверждать или отклонять каждую карточку;
- показывать активный provider/model и readiness;
- показывать число запросов, ошибок и токенов по типам сценариев;
- не показывать денежную стоимость для Ollama;
- добавить русские loading/empty/error states и доступную навигацию.

**Тесты вместе с кодом:** генерация, фильтры, подтверждение, отклонение,
повторные команды, пустое состояние, недоступный Ollama и usage statistics.

**Проверки:** frontend check, backend regression, production build и ручной
цикл generate -> preview -> accept/reject.

**Предлагаемый коммит:** `feat: add ai mentor interface`

## 3.7. Итоговая проверка Release 3

**Результат:** AI-функции воспроизводимо работают локально и не ухудшают
offline-first сценарии.

- добавить opt-in smoke для настоящего Ollama и `qwen3:4b`;
- проверить AI disabled и Ollama stopped;
- выполнить полный backend/frontend regression;
- выполнить миграции на чистой и существующей БД;
- проверить Docker networking и документировать доступ к host Ollama;
- пройти Answer Evaluator, Card Analyzer и Card Generator через production UI;
- проверить отсутствие автоматических изменений Card и SM-2;
- обновить README и критерии готовности.

**Итоговые проверки:** Release 2 check, migration check, AI fake-provider smoke,
opt-in live Ollama smoke, Compose health и ручные сценарии.

**Предлагаемый коммит:** `chore: finalize release 3 validation`

## Критерии готовности Release 3

- без Ollama приложение запускается и сохраняет все возможности Release 2;
- Ollama и модель проверяются независимо от core health;
- каждый AI-ответ проходит строгую Pydantic-валидацию;
- анализ ответа не меняет SM-2 без пользовательской оценки;
- анализ карточки не редактирует её автоматически;
- сгенерированные карточки создаются только после accept;
- повтор команды с тем же idempotency key не вызывает модель второй раз;
- usage logs не содержат prompts и пользовательские ответы;
- все AI-ошибки имеют стабильные коды и русское безопасное отображение;
- облачные провайдеры и Adaptive Tutor остаются за границей релиза.
